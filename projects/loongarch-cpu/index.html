Debugging story: stale state after an exception

An FPGA test intermittently stalled after the initial simulation passed. Varying memory latency reproduced the fault and traced it to fetch-buffer state surviving an exception flush.

Another failure came from stores taking effect in EX before an older exception reached WB. The fix required suppressing side effects early: a writeback flush could not undo a completed memory write.

Ownership & validation scope

Completed the initial individual CPU and pipeline labs, including forwarding and stall handling. In the later three-person project, I implemented exception and TLB-exception paths, worked on SRAM-like handshakes and AXI control, and integrated D-cache and uncached accesses. Teammates developed the standalone AXI bridge and base TLB/cache modules.

Reports record simulation and FPGA passes through several stages, including exp22. Later exp23 cache-maintenance work retained an unfinished CACOP mode=2 path.
