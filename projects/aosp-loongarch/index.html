Loongson Technology Corporation Limited · Jul.–Aug. 2024

AOSP / LLVM for LoongArch

Investigating a compiler-toolchain upgrade and system compatibility on an existing LoongArch Android port.

  • LLVM/Clang
  • Soong
  • Linux
  • Cross-compilation
  • Bionic
  • LoongArch64

Following a failure across the software stack

  1. Build configurationSoong modules, APIs, and toolchain selection.
  2. Compiler targetOptions and LoongArch backend support.
  3. System interfacesKernel ABI, Linux UAPI, and Bionic.
  4. RuntimeBoringSSL and ART architecture assumptions.

My contribution

  • Investigated duplicate Soong modules and API mismatches when integrating newer toolchain components.
  • Compared Clang option support and built LLVM/Clang from source to include the missing LoongArch target.
  • Built an ABI 2.0 kernel, regenerated Linux UAPI headers, and updated Bionic assembly for LoongArch.
  • Resolved three BoringSSL build errors recorded in my weekly reports and investigated remaining ART architecture and atomic-operation failures.

Engineering lesson

A compiler upgrade is a dependency problem across the build system, target support, headers, and runtime libraries. With guidance from colleagues, I narrowed changes to the necessary toolchain components and separated failures by build stage, making the source of each incompatibility easier to isolate.

Outcome

The work advanced target support and resolved specific build blockers on top of an existing port. Remaining ART and runtime issues meant the upgraded AOSP build was not fully validated end to end.
