System-call path

  1. User taskecall enters the kernel with a call number and arguments.
  2. Trap entryAssembly saves the register context.
  3. Kernel serviceC code dispatches the call and updates task state.
  4. ReturnWrite back the result and advance sepc.

What I implemented

  • ELF image construction, task metadata, and program-loading logic.
  • Ready/sleep queues, task scheduling, timer-interrupt handling, and RISC-V context switching.
  • System-call dispatch and process-control operations: exec, exit, kill, and waitpid; shell commands for interacting with tasks.
  • Synchronization and communication mechanisms, including barriers, condition variables, and mailboxes.

Working across C and assembly

Trap entry saves the interrupted register state, while the context-switch routine preserves the callee-saved state needed by the calling convention. The C side manages queues, process state, and kernel services.

One critical interface is the system-call handler: it reads the call number and arguments from the saved context, dispatches the service, writes the return value, and advances the saved program counter so the same ecall is not executed again.

Scope and remaining work

The project extends course starter code and uses the course toolchain, QEMU, and GDB workflow. Later branches explore multicore support and Sv39 virtual memory, but retain unfinished scheduler-lock and memory-management changes. Filesystem and networking notes describe later course work; they are not presented here as completed implementations.
